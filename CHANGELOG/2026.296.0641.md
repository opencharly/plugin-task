# 2026.296.0641 — feat(task): the `task:` hop carries the nested run's own report

Closes #33

## Summary

The `task:` hop — the seam a `verb:task` step crosses to compose a declared task — answered with a bare aggregate: `ran N task(s), M step(s) failed`. The **verdict** survived the crossing; the **evidence** did not. A caller that composed a verb through `task:` could see that the nested run PASSED and never what it reported: the wrapped verb's counts, its per-pin states, its producer-first leg order.

The umbrella's own `charly.yml` records the loss as filed at `opencharly/plugin-task#33` rather than paying for it by re-composing the pin verb — re-composing duplicated the six-entry `pin_map` and produced the contradictory `verify: 0` / `verify: 6` counts of `opencharly/opencharly#563`. This change pays it **once, at the seam**.

**What this change does.**

- `hopTasks` (new, in `candy/plugin-task/cli.go`) is the hop's composition, lifted out of the verb's inline loop in `invokeOpRun` so the **real** hop — not a helper beside it — is what the coverage drives. That is the `opencharly/plugin-task#12` lesson exactly: a test that drove a helper beside the call site passed even after the call site regressed to the bare aggregate.
- `hopSummary` (new) composes the hop's message. One message -> that message, verbatim. Several -> the non-empty ones joined, in plan order. None -> the aggregate, because a task with no steps has no evidence to carry and the count is all there is. A walk that ended with failures (a `continue_on_error` task failed a step and the hop kept walking) keeps the aggregate as the **prefix**, so the count of what failed is never lost.
- The **failure** path is unchanged: it stays selective and names only what failed, so a passing step never bloats a failure verdict. The `opencharly/plugin-task#12` behaviour is still pinned by the tests that predate this change, and they still pass.
- The live gate grows an arm that composes the **real pin verb** behind one hop and asserts its report crosses, beside the existing arm that a failing leaf's reason crosses.

**What this change does not do.**

- It does not enrich the top-level `res.Message`. The top-level reporter already prints every step line, so enriching it would duplicate the reason rather than carry it — the boundary the existing `TestNestedFailure_TopLevelNotEnriched` pins.
- It does not change the hop's pass/fail contract, the CLI's exit status, or the JSON report shape.
- It does not re-compose any verb in the umbrella, and it does not touch the umbrella's `charly.yml` comment that records the loss as filed here. That comment is the umbrella's own leg of the producer-first chain and is corrected in the umbrella's pin-bump PR (`opencharly/opencharly#621`), once this change has reached the umbrella's binary.

## Rulebook compliance

- **R0 — skills first.** The skills this repo's own `AGENTS.md` names for this area were read before the first edit: `/charly-internals:plugin` (the provider and the plugin's shape), `/charly-image:layer` (the candy's `charly.yml` and its plan steps), and `/charly-internals:git-workflow` (the branch, the commit, the PR). No schema and no candy entity changed, so the CUE rules of `/charly-internals:go` do not apply here.
- **R1 — every anomaly got a root-cause analysis, and every finding is fixed or filed.** The anomaly is the hop's evidence loss. Mechanism: the hop composed its answer from the walk's counts alone, and the nested run's step messages were dropped at the seam. Missed control: nothing asserted that a composed verb's report crosses the hop, and the pre-existing tests covered only the *failure* path — which is why the loss survived the `opencharly/plugin-task#12` fix. Blast radius: every consumer that composes a verb through `task:` sees a verdict and no report; the umbrella's `verify` is the one that bites, and it had already filed the loss as `opencharly/plugin-task#33`. Root fix: the hop carries the nested steps' own messages, the coverage drives the real hop, and the live gate grew an arm that composes the real pin verb behind one hop — the same shape the umbrella needs. **The finding raised on this change by its own gate was the discovery that a passing `command:` step's message is `exit=0` and not its stdout** (the stdout rides `CapturedValue`), so the live arm composes the *pin verb*, whose report is a real report, rather than a command whose message would prove nothing. That is fixed in the control — the arm — and not worked around.
- **R2 — one implementation.** The hop's composition lives in `hopTasks` and its message contract in `hopSummary`; the aggregate string is defined in exactly one place (the sweep above). The umbrella's re-composition workaround stays deleted — this change does not bring it back.
- **R3 — no workaround.** The hop carries the evidence the nested run already produced. Nothing sleeps, retries, re-runs, or falls back to a second execution path, and no failure is suppressed: the failure path is byte-for-byte the path that shipped.
- **R4 — the product was fixed before the prose.** The Go source and the live gate are the change; no documentation claims anything this change does not do, and the only prose about the loss is in another repo, corrected in that repo's own leg.
