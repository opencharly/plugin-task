### Finding 1 — a non-positive bound was honoured instead of refused

**Expected.** A bound of zero or less is not a bound: it marks EVERY not-current pin stale,
which is the permanently-red gate this knob exists to avoid.

**Actual.** `stale_after: "0s"` parsed and was applied. The live gate reports
`1 STALE pin(s) (neglected for more than 0h)` — the permanently-red verdict, reached
through the operator's own hand.

**Mechanism.** The parse block rejected only text `time.ParseDuration` could not read. Any
duration it could read was accepted, and the positivity of the bound was never tested.

**Missed control.** The knob's contract is enforced at the *reading* side (the age is
compared against the bound) and never at the *bound* side (whether the bound is a bound at
all). Every arm in the unit test and in the live gate exercised a positive bound, so no arm
could reach the gap.

**Blast radius.** Only a repo that declared a zero or negative bound. The knob is opt-in and
no repo declares it yet, so nothing in the org is affected today.

**Root cause.** The value was validated as a *duration* but not as a *bound*.

**Root fix.** A non-positive duration is refused in the verb — the canonical place — with a
message that names the reason. Covered by a unit arm (three values: `0s`, `0`, `-1h`) and by
a live arm that asserts both the refusal and the absence of any staleness judgement.

### Finding 2 — a failed history read was reported as neglect

**Expected.** A pin whose age cannot be measured is not reported as neglected. An unknown
age is not a claim that the owner neglected the pin.

**Actual.** An unreadable history produced `it has never been advanced here` and a STALE
verdict — a claim about the owner's conduct, backed by no evidence.

**Mechanism.** `lastAdvancedAt` returned `(time.Time{}, false)` for every failure mode of
`git log`, and the caller read the single `false` as "never advanced". But two different
things arrive at that same exit status: a repo with **no history** (the path is in no commit
— a FACT, and it is neglected) and a repo whose history **cannot be read** (a broken object
store, a transient git failure — the age is UNKNOWN).

**Missed control.** git reports those two conditions identically, and nothing in the verb
told them apart. Measured before choosing a discriminator: `git log` exits 128 for an unborn
HEAD ("does not have any commits yet") and 128 for a broken object store ("fatal: bad object
HEAD"); `git rev-parse --verify -q HEAD` — the first discriminator reached for — exits 1 for
BOTH an unborn HEAD and a broken HEAD ref, so it cannot separate them either. The
discriminator that works is `git rev-list --all --count`: zero commits means there is nothing
here that could have been advanced (the fact), a count that cannot be produced means the
history cannot be read (the failure).

**Blast radius.** Any repo whose object store is temporarily unreadable. The verdict would
name a pin STALE on no evidence, and the owner would be told to do work that is not the
cause.

**Root cause.** One absence — no age — carried two meanings, and one of them was a claim the
evidence did not support.

**Root fix.** The read now has three outcomes, and only one of them is a claim about the pin:
a **measured age**, **no-history** (the path is in no commit of this repo's history, so it
has never been advanced here — and it IS neglected), and **read-failed** (the age could not
be measured — the workflow being unable to JUDGE the pin, which is a structural-class
failure naming the read error). The read-failure case is routed to the structural class
precisely so that a transient git error can never manufacture a stale verdict. Covered by a
unit arm (a removed HEAD commit object) and by a live arm that asserts the verdict names the
read failure and carries no STALE pin.
