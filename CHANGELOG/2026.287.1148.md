# 2026.287.1148 — fix(git-submodules): report what actually changed, and lead with what failed (opencharly/opencharly#477)

## Summary

`charly task sync` — and the `git-submodules` verb under it — reported what it *visited*, not what it *changed*, and hid the reason whenever it failed. Reproduced on the live umbrella against `opencharly/opencharly#477`.

**Four measured symptoms, all on this change's own path:**

```
$ charly -C . task sync                                        rc=1
task sync: 1 step(s), 1 failed
  [fail] run — bump the pins (charly rolls first, then distro-* from its new gitlinks)
      task "pins" failed (1 step(s) failed)
        [fail] run — run git-submodules in the selected mode
            bumped 422 submodule pin(s): action-review, charly, charly-alpine, … distro-ubuntu, docs, dotgith
charly: error: command "task": task "sync" failed (1 step(s) failed)

$ git status --porcelain
 M sdk
 M spec                                            ← TWO staged, not 422
```

1. **The count names the wrong collection.** `case "bump"` (verbs.go:292) has two phases: phase 1 rolls every submodule *not* named in `pin_map` into `done`, phase 2 appends the `pin_map` entries that pinned into the *same* slice, and the summary prints `len(done)` as "pins bumped". The arithmetic is exact — **428 submodules − 6 uninitialized = 422**, and the read-only `verify` task prints those same two numbers as *"422 checkout(s) clean at their gitlink; 6 uninitialize[d]"*.
2. **The failure report is truncated away.** The `StatusFail` branch appends `"; %d FAILED: %s"` **after** 422 names. The runner truncates the message, so the clause that explains the failure never arrives — although the verb's own comment promises *"every failure is reported together at the end, so the run's own output names all of them."* **An ordering that makes that promise unkeepable.**
3. **The non-zero exit is therefore unactionable.** `rc=1` with no visible reason.
4. **A task described as a preview moves checkouts.** Phase 1 rolls each submodule to `origin/<branch>`, which left `sdk` at `884e2d8` and the umbrella dirty until restored by hand.
