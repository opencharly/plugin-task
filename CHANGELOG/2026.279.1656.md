# 2026.279.1656 — fix(plugin-task): make `git-submodules verify` audit every submodule checkout

## Summary

`verb:git-submodules`'s `verify` mode documented a two-clause assertion and implemented one:
it compared every `pin_map` gitlink against `pinned_from`'s twin (policy B) and never read a
submodule's worktree, so **"every submodule is clean + at its recorded gitlink" was never
asserted** (plugin-task#10). This PR implements the missing clause, and closes a second gap the
issue named: on the pass path a `command:` step's stdout is discarded, so the verb's `Message`
is the only channel that can put a gate's coverage on the record.

Three changes, all inside `candy/plugin-task/verbs.go`:

1. **Half 2 of `verify`, over every `.gitmodules` path.** The recorded gitlink must be present in
   the index; where a checkout exists it must be **clean** and its `HEAD` must **be** that
   gitlink. Every read goes through `submoduleAt`'s walk-up-safe `--git-dir`/`--work-tree` form
   (the #8 / charly#768 fix), so a present-but-uninitialized directory can never resolve to the
   enclosing superproject's `HEAD` — the failure mode that made the umbrella's hand-rolled copy
   of this loop compare the UMBRELLA's HEAD against 405 of 424 submodule gitlinks
   (opencharly/opencharly#337).
2. **The recorded gitlink is read FIRST, for every declared path; the checkout is classified
   after it.** An index read needs no worktree, so a path declared in `.gitmodules` with no
   recorded gitlink now FAILS by name (`<p>: no gitlink recorded in the index`) instead of being
   reported as an audited pin. Only then is the checkout classified: an initialized one must be
   **clean** and its `HEAD` must **be** the recorded gitlink, and an **uninitialized** one is
   counted and named in the `Message` — never silently skipped, never counted as a clean
   checkout. Calling the missing *checkout* a failure would make the verb unrunnable exactly where
   the gate needs it (a session worktree initializes no submodule at all), and silently dropping
   it is what the issue is about in the first place.
3. **Policy-B failures are COLLECTED, not first-return.** One run now names every failing path
   instead of stopping at the first, and the failures are sorted so the message is stable.

The doc comment and the code now agree, which is the whole point: a documented clause nobody
implements is a gate that reports coverage it does not have.

**This head answers the review of the first one** (`6020891644`, head `b1045fc3`, `BLOCK`), and
its Block 1 was correct — it found the same class of defect inside this fix. The loop classified
a path as uninitialized *before* reading the index gitlink, so `gitlink()` never ran for those
paths and a `.gitmodules` path with no index entry passed as `uninitialized (pin audited)`: the
vacuous-coverage hole half 1 exists to close, reintroduced one branch over. The loop is reordered
(the read is unconditional and comes first), the loop comment, the doc comment and the pass
`Message` are corrected with it, and the test gained the arm that pins it — item 4 below proves
that arm discriminating against the pre-fix code. Block 2, the missing `(<confidence>)` slot in
the `Assisted-by:` trailer, is fixed at the foot of this body.

**Not in this PR:** the umbrella's `verify` step still hand-rolls its own `git -C` loop. That copy
is deleted by the tracked successor **opencharly/opencharly#403** — *verify: compose
`verb:git-submodules` for the checkout audit and delete the hand-rolled loop* — producer-first
(this verb merges → the umbrella's `plugin-task` pin advances → the step composes
`verb:git-submodules` and the loop goes). Doing it in this PR is impossible — different repos —
so the ordering is the org's producer-first sequence, not a deferred half of this change. #403 also
records a second measured consequence: the umbrella's hand-rolled copy echoes its coverage from a
`command:` step, whose stdout is discarded on the pass path, so its gate transcript renders that
step as a bare `exit=0` — the verb's `Message` is the channel that renders.
