# 2026.299.2314 — fix(git-submodules): the nested-work refusal's scope is the REFUSED SUBMODULE (plugin-task#56)

## Summary

The refusal that landed in opencharly/plugin-task#55 (for opencharly/plugin-task#54) refuses the right move — a nested checkout that carries work is not moved, and the path, the commit and the recorded pin are named. But three surfaces described a SCOPE the product does not have: the code comments in `candy/plugin-task/verbs.go` and the record `CHANGELOG/2026.299.2250.md` said the refusal "leaves the tree exactly as it was" and "stops the whole bump with the tree untouched".

**The product's contract is PER-SUBMODULE.** `bump` collects a per-path failure and CONTINUES — opencharly/plugin-task#13: "ONE path's per-invocation failure costs that ONE pin, not every pin sorted after it", proven by `TestGitSubmodules_BumpContinuesPastFailure`. So a path that sorts earlier has already been rolled and its pin staged by the time the refusal is reported.

**THE MEASUREMENT** — an umbrella that pins two submodules, the paths SORTED, so `outer` — the one whose nested checkout carries the operator's commit — is refused FIRST and the sibling `zebra` is visited AFTER it:

```
bump: fail: 1 pin(s) FAILED: the nested checkout outer/inner carries a commit the update would drop — its HEAD 53c39a005831366d1963dd8cad25e1ffdb66e5ef is in no branch, tag or remote-tracking ref of that checkout (the recorded pin is 4a689d112e7d64a25990149e80dbe7db18d15382), so the update would move it off that commit and leave it in the reflog alone; push it, branch it, or stash it, then re-run; rolled 1 submodule(s) to their default-branch HEAD; advanced 0 pin(s) in the index; pinned 0 pin_map entr(y|ies):
```

`rolled 1 submodule(s)` and one refusal: the sibling was rolled and its pin staged, and the refusal stopped the OTHER submodule. The tree was not untouched — the REFUSED SUBMODULE was.

**What is corrected is the SENTENCE, not the behaviour.** The refusal preserves the work and names the nested checkout that carries it, exactly as #54's own measurement shows; and the umbrella's initializer — the policy #54 named — is per-path too ("a divergent nested twin is reported and left alone" while the parent advances, `scripts/init-submodules.sh`). Making this refusal abort the whole wave would strand every pin sorted after the refused one, for a reason the operator can fix in one checkout.

**The scope becomes MECHANICAL instead of a prose assertion** — and this is where the review of the first round of this pull request landed, and it was right. The scope is only OBSERVABLE when the refused path is visited BEFORE the path that survives it: the walk visits the paths SORTED, so a refusal stops a path that has already been rolled, and a path that sorts after it is rolled only if the walk CONTINUED. The first round's fixture put the sibling BEFORE the refused path, and under that order a walk that ABORTED at the first failure left the same final state as one that continued — the test asserted the outcome and called it proof.

**The scope is now held by a control that DISCRIMINATES.** The sibling is `zebra`, which sorts AFTER the refused `outer`; the test reads the order from the product's OWN path reader and ASSERTS it, so a change in the order fails loudly instead of silently making the test blind; and the scope is proved against THREE live mutants of the walk, each on the SAME test file — the refusal ignored, the walk aborting at the first failure, and the path order reversed. Each turns the test RED, on a different assertion. The transcripts are under **How tested**.
