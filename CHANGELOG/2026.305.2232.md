# 2026.305.2232 — feat(verb): pin-closure — the transitive closure of a pin advance, iterated to a fixed point

## Summary

Adopting a pin in a multi-module repo is never one edit: each module that pins a repo also pins its **siblings**, so advancing one pin surfaces the next module's breakage, and the next. `verb:pin-closure` answers the whole question in one word — **compile the composed set, collect EVERY failing module, classify each failure as a BUMP (a published version already carries the fix) or an EDIT (none does — that module needs its own cutover), and iterate to a fixed point** (opencharly/charly#906).

What lands, in `candy/plugin-task/`:

- **`pin_closure.go`** — resolve the pair, write a `go.work` overlay over the anchor module plus any already-composed dirs (they win over the pins), build, parse the failures into per-module verdicts, classify against the module the **failing package** belongs to, and report an **EMPTY** closure, a **BUMP** list, or a **REFUSED** advance naming the EDITs.
- **`schema/task.cue` + `params/cue_types_gen.go`** — `#PinClosureInput` (`anchor`, `compose`, `module_prefix`). The generated types are **regenerated from the schema** with `charly candy params` (drift gate `--check` clean) — which is also how the `cue_types_gen.go` conflict against current `main` was resolved, rather than hand-merging a generated file.
- **`plugin.go` / `verbs.go` / `charly.yml`** — declare and route the sixth maintenance verb; the candy's capability probe now asserts all nine (three task classes + six verbs).
- **`AGENTS.md` / `README.md` / `scripts/gate-task.sh`** — the five→six arithmetic corrected **in the same change** (R5: no stale count survives), and this repo's own live gate now **drives the new verb** (see How tested).

**Round 1 review fixes, in this head** — all three blocks were right, and two were product defects:

1. **The bump's version lookup and its `replace` key did not agree.** `newestModuleVersion(anchor, f.Pkg)` was handed a **package** path while `replaces[closureModule(f.Pkg)]` keyed the replace on the 3-segment "repo root" — so for a subdir module (`github.com/opencharly/org/repo/candy/plugin-x`) the lookup asked the toolchain about a path that is not a module (BUMP unreachable, every failure forced to EDIT) and any replace it wrote targeted the wrong module. **`moduleOf` now asks the toolchain** (`go list -f {{.Module.Path}}`) and both the lookup and the replace use that one path; `closureModule` is the documented fallback and no longer claims a resolution it never did.
2. **`writeOverlay` hardcoded `go 1.26.4`** into every generated workspace — over-constraining every closure build to one toolchain (a module declaring `go 1.24` was built under a workspace demanding 1.26.4) and failing on an older host. The `go` line is now the **anchor's own directive** (`workspaceGo`), with a conservative floor only when its `go.mod` cannot be read.
3. **The headline — "iterate to a fixed point" — had no witness**: both gate fixtures end at rung 1 with nothing adopted. It now does, **hermetically**: `TestRunPinClosure_IteratesToAFixedPointAfterABump` builds a real three-module fixture (a pinned dependency whose own package does not compile, and a newest version that does), swaps only the version-lookup seam, and requires rung 1 to see the breakage, classify BUMP, **adopt** it, and rung 2 to compile.

**Round 2 review fixes, in this head** — one real defect in the verb itself:

- **A re-failing adopted module was silently dropped, and reported as `advance: CLEAN`.** A module classified BUMP at rung 1 and adopted was skipped at rung 2 by the `verdicts` map, so when its newest version fixed the *named* symbol but the composed set **still** failed, nothing recorded it: `edits` stayed empty and the report claimed the pair needed "only a pin bump" about a module that provably does not compile — the false-BUMP direction `classifyClosure`'s own comment warns against. It is now recorded as an **EDIT** carrying the failure that proves it, so the report REFUSES the advance. `TestRunPinClosure_AdoptedButStillFailingIsAnEDIT` is the guard, and reverting the fix makes it fail on exactly those two assertions.
- `firstLines`' doc comment had been left above `workspaceGo` (a comment describing a different function than the one it precedes) — moved back onto `firstLines`.
- `goTmpDir` handed the toolchain a shared `GOTMPDIR` it never created, so a fresh host could fail its own temp-file creation; the dir is now made, falling back to the toolchain's default when it cannot be.

An adopted module is now replaced by its **downloaded dir** when the lookup resolved one (`adoptionTarget`): the source is already on disk, and a version form would make the next build re-resolve it — needing the network mid-build and, for a module the registry cannot serve, reintroducing exactly the failure this verb exists to find.

Also fixed from the gate's own first run: the workspace build inherited an ambient `GOFLAGS=-mod=mod` and failed with `go: -mod may only be set to readonly or vendor when in workspace mode` — `runGo` now drops `-mod` for the workspace build and keeps every other flag (`TestGoFlagsWithoutMod`).

**Re-cut onto current `origin/main`** (the previous tip was 33 commits behind and main had moved `verbs.go`): the single content commit was re-applied on a fresh branch off `origin/main`, nothing was force-pushed, and the old branch is untouched.
