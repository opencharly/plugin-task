# 2026.281.2157 — fix(git-submodules): report an uninitialized checkout once, naming which ones

## Summary

Fixes `opencharly/charly#864`. `charly task sync` over a fresh worktree **bumped what it could and then failed once per uninitialized submodule** - 422 identical failures in the measured case - because each path failed independently in the walk that is deliberately resilient (`plugin-task#13`).

**The two counts above differ because they are two different artefacts - 422 is the measured tree, 1 is the fixture - and neither is extrapolated from the other.**

**The condition is not one of those per-path failures.** An uninitialized checkout has no pin to advance - the `status` mode already says so as a marker - so it is a **precondition** and is now pre-flighted **once** and reported **once**, with the count, the affected paths, and the command that repairs them.

```
# (1) the MEASURED case - a real `charly task sync` in a fresh umbrella worktree, pasted in charly#864:
before:  bumped 1 submodule pin(s): charly; 422 FAILED: submodule "action-review" is not an initialized checkout ...
# (2) the SHAPE after the fix - the unit/gate fixture, which carries ONE uninitialized submodule:
after:   bumped 0 submodule pin(s): ; 1 submodule(s) not an initialized checkout (action-review): run `git submodule update --init`
```

## Three invariants read from the code and its tests, BEFORE writing any of it

Each one narrowed the change, and the first two killed an earlier attempt:

1. **`charly#768` - the loud failure is the FIX, not the bug.** Pre-`#768`, `git -C` inside an uninitialized submodule **walked up and detached the umbrella worktree** from its branch. The pre-flight performs **no git operation** in those directories - it tests for the submodule's own `.git`, exactly as `submoduleAt` does before refusing - so the guard and its regression assertion (umbrella HEAD and branch untouched) both hold, and a sync over a tree it could not fully advance **still FAILS**.
2. **Only `bump` fails on it.** `status` is *designed* to report an uninitialized gitlink as a marker and succeed (`TestGitSubmodules_StatusUninitializedMarker`), and `verify` judges policy rather than checkout availability. Both keep their behaviour exactly.
3. **`plugin-task#13` - one condition never strands the rest.** Pins that *can* advance still do.

The refusal also keeps the guard's own vocabulary (`not an initialized checkout`), because that phrase is what existing readers match on - including the regression test.
