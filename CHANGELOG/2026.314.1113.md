# 2026.314.1113 — refactor(schema): derive the task mode word sets from vocabulary tables

## Summary

Convert the five `mode` word unions in `candy/plugin-task/schema/task.cue` to the §10.1 S3
vocabulary-table idiom, so each closed set of words has ONE home and the enum an author
meets is `or()` of that table's keys:

```
_submodulesMode  _checkSync  _pruneMode       (+ their derived _…Word lists)
```

That is the 4 `union` rows `design/dpat-baseline.tsv` records for this file, and the row
count is a property of the OLD file's FORMATTING: **four distinct lines, five FIELD SITES**.
`mode?: "sync" | "check"` appears twice — `#SpliceRegionInput` and `#ModulePinsInput`, written
identically — so the census records it once with a count of 2. So **THREE tables cover FIVE
fields**:

| table | words | fields |
|---|---|---|
| `_submodulesMode` | 4 | `#GitSubmodulesInput.mode` |
| `_checkSync` | 2 | `#FileParityInput.mode`, `#SpliceRegionInput.mode`, `#ModulePinsInput.mode` |
| `_pruneMode` | 2 | `#PruneInput.mode` |

`_checkSync` is the one two-word set three verbs share, so it has ONE home and three
consumers rather than three copies that could drift apart (R2). No union in this file
carried a default, a scalar-type alternative, or a heterogeneous or struct alternative;
nothing is left to judgement.

The accepted sets are IDENTICAL before and after — 4 / 2 / 2 / 2 / 2 words, read from the
compiled CUE on both sides (163-case differential in §4).

**The generated projection does not move at all.** `charly candy params plugin-task --check`
says `current` on the pristine tree and again after the sweep, so this diff carries no
`params/cue_types_gen.go` change: every generated type, field and tag is byte-identical.

Files the diff carries:

