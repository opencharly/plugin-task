# 2026.297.2014 — test(task): the stdin exclusion proves its precondition, and every test pipe is closed

## Summary

The `charly/pr-validator` report on the DATA channel PR (`opencharly/plugin-task#47`) ended with four minor observations. Two of them are findings on the code that PR landed, so R1 makes them fixed here rather than filed away, and this change fixes them. The change is 2 files, +21 −3 (Head `13b7bc7db5f7d694e5d32c3029979e0a1929d5d2`).

**1. The stdin-exclusion test proved an absence without proving the cause.** `TestRunTask_StdinBytesAreNotExported` asserted that `TASK_STDIN` and `TASK_STDIN_FILE` are not in the step's exported environment. That absence is satisfied by two different worlds: the capture ran and its vars were correctly excluded from the export, or the capture never ran at all and of course nothing was exported. The second is a vacuous pass. The trigger for the capture (`taskConsumesStdin`, and stdin not being a terminal) was set up by the test but asserted by nobody, so a regression that stopped the capture would have left the test green.

The test now asserts the precondition POSITIVELY: the capture ran, so the task's own merged env carries the piped bytes, while the step's exported env carries the resolved value and not the stream. `kit.Runner.EffectiveEnv()` is the task's merged env and `kit.Runner.StepEnv()` is the exported clone, and `newTaskRunner` hands back both, so the test sees the two maps side by side and asserts the difference rather than only the absence.

**2. Five of the repo's eight test pipes leaked their read end.** Four were in `runner_test.go` — the three `captureStdin` tests and the `runTask` truncation test — and the fifth was the stdin-bytes test in `stepenv_test.go`. The gating test in `runner_test.go` and both pipes in `capture_test.go` already closed both ends, so this change applies the file's own pattern to its siblings rather than inventing one.

The other two of the four observations are not defects, and their dispositions are on the PR's thread and on #48: the gate arm's leftover file lives inside the gate's own work tree (`PROJ="$WORK/proj"`), which the gate removes on exit (`trap 'rm -rf "$WORK"' EXIT`); and the dependency surface the SDK bump brings is the SDK's own (`loaderkit -> deploykit -> buildkitdrive`), not this module's.

Closes #48.

### RCA

- **Mechanism.** The test proved an ABSENCE without proving the CAUSE. An absence assertion is only as strong as the state that produced it, and the state was never asserted.
- **Missed control.** The landed change's own gate exercised the export path (its mutation dropped the param from the map) and never the capture path, so a mutation that removed the CAPTURE rather than the CLONE would have been invisible to it.
- **Blast radius.** The invariant is load-bearing: the export map reaches the command verb, which renders an exported value into the command TEXT, and a NUL byte in a piped binary stream would make the exec un-runnable (`fork/exec /usr/bin/sh: invalid argument`). A test that can pass for the wrong reason does not protect that.
- **Root fix.** Assert the precondition, so the test fails whenever the capture does not run; and close every pipe.
