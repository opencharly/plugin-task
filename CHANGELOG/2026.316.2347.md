# 2026.316.2347 — feat(schema)!: own the kind:task body here, declare its InputDef, take the helpers home

## Summary

**Leg 1 of unit 2's four-leg decomposition** (`TODO.md` 2.1, tracker `opencharly/spec#304`, row 2; unit 1 was the `pipeline` kind — `sdk#501`, `charly#1124`, `plugin-pipeline#63`, `plugin-pipeline#64`, `sdk#502`, `spec#305`, `charly#1126`). A `kind` body belongs with the plugin that serves the kind, so the `kind: task` entity body moves out of the contract module into this repo's own CUE module — and the `kind` capability **DECLARES** the gate def (`InputDef: "#TaskValue"`) in the SAME change, which is the contract `spec#304`'s unit-0 note records: without the declaration the host falls to the flat plugin-input path (concrete, not closedness-only) and authored bodies start failing.

The four legs, and where they stand: **1 this PR** (`plugin-task` owns the body + the helpers) → **2** `sdk` deletes the four task-shaped helpers → **3** `spec` deletes `#Task`/`#TaskValue` and regenerates → **4** `charly` bumps its `plugin-task`/`sdk`/`spec` requires in lockstep and retargets the three fixtures that name `#TaskValue`.

**`#TaskParamSpec` deliberately does NOT move**, and that is the one correction this unit's own plan needed: `plugin-pipeline`'s schema types a pipeline's `args:` as `{[string]: schema.#TaskParamSpec}` (`plugin-pipeline/candy/plugin-pipeline/schema/pipeline.cue:354`), and a plugin's CUE module can import only the contract module — never another plugin's. Moving it would let `kind: task` and `kind: pipeline` disagree about what an arg value is (R2), so it stays a contract def, exactly as unit 1 kept `#PipelineClassRoutes`.

### What changed

- `schema/task.cue` now declares `#Task` and `#TaskValue` and imports `github.com/opencharly/spec/schema` for the SHARED grammar (`#Step`/`#Op`), `#StrVal`, `#Duration`, `#EntityRef` and `#TaskParamSpec`. The import resolves offline through `spec/schemacompose` on BOTH sides (the serve side composes it; the host composes the same body under the derived module declaration) — the shape `plugin-pipeline#63` measured live.
- `params/cue_types_gen.go` is regenerated in process by `spec/schemaparams.Generate` — `params.Task` is field-identical to the deleted `spec.Task` after stripping the package qualifier (measured below). The referenced scalars stay the contract's: `spec.EntityRef` / `spec.Duration` are hand-written aliases in `spec/scalar_aliases.go`, `spec.Step` / `spec.TaskParamSpec` are generated there.
- The capability is `{Class: "kind", Word: "task", Validates: true, InputDef: "#TaskValue"}` — one line, and the host now resolves the gate through the provider's declaration instead of the base's `spec.KindValueDefs` fallback.
- The four task-shaped helpers come HOME from `sdk/workflowkit`: `resolveArgs` + `mergedEnv` (`resolve.go`), `closure` + `sortedNames` (`closure.go`). They lived in the SDK because its pipeline lowering was their second caller (`plugin-task` CHANGELOG 2026.277.0711); unit 1 moved that lowering into the plugin that owns the pipeline kind, so the second caller is gone and a helper typed on `spec.Task` cannot stay in a kind-blind mechanism library. `workflowkit.ResolveTaskDir` / `ExpandVars` stay in the SDK — they take strings and are shared.
- The four closedness cases of `spec/schema/task_test.go` move here as `task_schema_corpus_test.go`, judged through the **served** schema, BEFORE the contract module's twins are deleted (the 29+5-case lesson unit 1 measured).
- `schema_served_test.go` composes the served body through `schemacompose.ServedText` instead of `CompileString` — the schema imports the contract module now, and a package-less compile cannot resolve an import (two sites). `params_repro_test.go` joins it so the generated file is proven current and reproducible.
- The sdk/spec requires move in LOCKSTEP to the current merged tags (`sdk v0.2026316.1848`, `spec v0.2026316.1928` — exactly `charly`'s own pins), because the in-process `schemaparams.Generate(schemaDir, pkg)` this repo needs only exists from `spec v0.2026313.1428` (older versions shell out to the `cue` CLI, which cannot resolve the import), and because a `spec`-only bump breaks the older pinned sdk, whose `workflowkit` still names `spec.Pipeline` (deleted by unit 1).
- The docs follow the code: the candy description, the repo `AGENTS.md`, and every comment that named the base schema as the body's home.

## Change classification

**Breaking change + rollback:** this is the first half of a hard cutover, so it changes the plugin's own contract in two ways: the entity body is now validated against THIS plugin's `#TaskValue` (resolved from the declared `InputDef` rather than the base map — the base still declares the same def until leg 3, and the two compose to an identical value, which the corpus sweep measures), and the plugin's Go surface now exposes `params.Task` instead of `spec.Task`. Nothing outside this repo consumes either: `spec.Task` has no other reader (the SDK's four helpers are its only other site and leg 2 deletes them), and no project authors the def by name. Rollback is a revert of this commit: the contract module still carries `#Task`/`#TaskValue` until leg 3, and this repo's previous revision declared no kind `InputDef`, so the host's old fallback route is intact.
