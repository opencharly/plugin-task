# 2026.268.0534 — fix(verbs): correct the git-submodules bump ORDER (RDD — policy B violated)

## Summary

Fix a real ordering defect in `verb:git-submodules` `bump`, caught by RDD while
consuming the verb for the umbrella cutover.

**The defect.** `bump` pinned the `pin_map` entries FIRST, then rolled every
non-pinned submodule — but the `pinned_from` repo (e.g. `charly`) is itself one of
the ROLLING submodules. So it pinned the `pin_map` entries FROM `pinned_from`'s
**old** HEAD, then advanced `pinned_from`, leaving policy B (the umbrella's
`distro-*` gitlinks must equal charly's gitlinks) **violated after every sync**.

**The fix.** Phase 1 rolls every submodule not named in `pin_map` to its
default-branch HEAD (including `pinned_from`); phase 2 then reads `pinned_from`'s
**now-current** gitlinks to pin the `pin_map` entries.

## How tested

`TestGitSubmodules_BumpOrder` builds REAL submodules where `pinned_from` (`src`) is
a stale rolling submodule whose `inner` gitlink advances (`L1` → `L2`) during the
bump, and asserts the `pin_map` entry lands on src's **NEW** gitlink `L2`:

```
$ go test ./... -run 'TestGitSubmodules'
ok  	github.com/opencharly/plugin-task/candy/plugin-task
```

Proven with teeth: making phase 1 skip `pinned_from` turns it RED
(`target pinned to … want L2 … L1 means it read stale src`).
