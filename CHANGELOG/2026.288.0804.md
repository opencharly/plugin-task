# 2026.288.0804 — feat(git-submodules): a pin declares its INTENT; `currency` is a first-class mode; an edge over an edge is refused (opencharly/charly#936)

## Summary

Closes #29. Replaces the CONTRACT, not the verb: `pin_map`/`pinned_from` and every existing mode keep working unchanged, and CURRENCY becomes answerable instead of assumed.

**Why.** `verify` asserts CONSISTENCY — that each checkout matches the gitlink the INDEX records — and a tree can be perfectly consistent while every pin is behind what its repo serves: `verify` was GREEN while five of six `distro-*` were behind their remotes. The chain it settled for had no intended value anywhere: the umbrella's pin equals charly's gitlink in **6/6**, but charly's gitlink equals its own `import:` tag in **1/6** and the distro's served `main` in **1/6** (a different one) — in **4/6 it equals neither**. A check satisfiable at both ends while both ends are stale is a mirror, not a contract.

**What this adds.**

- **A pin declares its INTENT** (`intent:`). `upstream:<ref>` is a LEAF, judged against the REMOTE with no local state in the answer; a `pin_map` entry is an EDGE, judged by whether the SOURCE's OWN pin at the twin path is current — **one hop FURTHER than its gitlink**, read from the source repo's `.gitmodules`, which is where that ref is declared. An intent nobody wrote down but which `bump` already implements is STATED in the report, never left silent.
- **Two structural rules.** An edge may not point at another edge (depth ≤ 2), so the graph is acyclic BY CONSTRUCTION rather than by a validation that can be skipped — and the rule is enforced against **EVERY** edge source, `pinned_from` **and** each explicit `derived-from:<path>`, because a rule kept at one call site is a rule the next edge SHAPE walks around. Every leaf must be remote-verifiable. That is the whole difference from the contract this replaces.
- **The states, named:** `cur`, `behind`, `blocked-by <source>:<twin> (<state>)`, `not-on-the-served-line`, `unpinned`, `pin-mismatch`. The FAILURE set is the STRUCTURAL one — a pin whose ref nobody declared, an edge whose two sides disagree, a source that declares no ref for the twin, an unserved ref, the depth violation. `behind` and `blocked-by` **PASS and are REPORTED**: they are legs of a cross-repo sequence whose next step is another repo's PR, and a gate that failed on them would be permanently red, which trains every reader to ignore it — the mirror problem inverted. **The Message therefore LEADS with the number of pins that are not current**, names each one with its intent and both SHAs, and prints the producer-first leg order.
- **The mode reads no checkout state**, deliberately: the index-vs-checkout seam (`opencharly/opencharly#461`) cannot arise in a walk that never compares those two objects.

1. **R7/R1 — the documented `derived-from:<path>` shape is now IMPLEMENTED.** The schema is the
   single source of truth and it documents TWO edge shapes; the code judged both against
   `pinned_from`, so an explicit `derived-from:other` was answered as a question about a repo it

   a `pin_map` entry derives from another CHECKOUT (value: that checkout's gitlink for the twin;
   currency: the state of the source's OWN pin there — one hop further), while an explicit
   `derived-from:<path>` derives from a SOURCE PIN OF THIS REPO (value: that pin's recorded
   gitlink read here; currency: that pin's own state). A source that records no gitlink is refused
   BY NAME. `TestGitSubmodules_CurrencyJudgesAnExplicitDerivedFrom` drives both arms.

   second look in round 3.** It was write-only because the in-repo edge shape that reads it was
   missing; implementing `<path>` made it live, so consuming it was right then. But round 3's
   depth guard pre-empts that read for any source that is itself an edge, which retired the
   pass-2 write: the map's whole supply is now pass 1. The dead write is DELETED in round 3, with
   the reason recorded where it stood. A fix that is right at one head is not automatically right
   at the next, and this bullet is the record of that.
3. **R5 — the sweep is pasted above, executed.**
4. **A1 — the footer is now in the exact italic form.**

**The missed control (R1).** The schema grew a second edge shape and the test suite exercised
