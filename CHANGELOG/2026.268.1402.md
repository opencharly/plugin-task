# 2026.268.1402 — fix(cli): render a step's Result.Message in text mode

## Summary

`charly task`'s text reporter (`printResultText` in `candy/plugin-task/cli.go`)
printed only each step's authored `Text`, never the step's `Result.Message`.

That message is the **only** carrier of a verb's own output:

- `verb:git-submodules` puts its `PATH BRANCH PIN` status table (mode `status`) and
  its `bumped N submodule pin(s): …` summary (mode `bump`) there;
- `verb:command` reports its `exit=N` there;
- and **any FAIL's diagnostic** (`exit=2, want 0 (stderr: …)`) lives there.

The check engine's own `report.renderStep` already emits `step.Result.Message` for
every step, so this plugin was the odd one out.

`formatStepLine` now renders `Text` **plus** the message; a multi-line message is
indented, never truncated, so a verb's table survives verbatim.

## Scope boundary — `charly task map`'s inline shell is a SECOND, separate defect

This PR fixes the **reporter**: it now renders whatever `Result.Message` a step
carries. It does **not** make the umbrella's current `map` task print, because
`map` uses an inline `command:` step, and the `command` verb's PASS path returns
only `exit=N` (its stdout is asserted via matchers, never echoed). That is a
distinct defect in `opencharly/plugin-command`'s pass path, plus an R3 duplication
in the umbrella's `map` (it re-implements the `verb:git-submodules status` table
as shell).

Both are routed to named work, not deferred into this PR:

- **opencharly/opencharly** — fix the umbrella `map` task to compose
  `verb:git-submodules status` (the canonical implementation) instead of the
  duplicated inline shell; it then renders via this PR's reporter. Opened as a
  named PR after this change's plugin version is available to charly.
- **opencharly/plugin-command** — the `command` verb's pass path discards stdout;
  a `run:` step that is expected to produce output has no way to surface it. Named
  for its own cutover.

This PR's own change is complete and independent: it is the reporter contract, and
the two live BEFORE/AFTER pairs above prove it end to end.
