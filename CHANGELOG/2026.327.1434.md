# 2026.327.1434 — feat(pins): the currency report states each pin's tag, and tallies it

## Summary

`charly task pins --param MODE=currency` answered "is this pin CURRENT?" from the recorded gitlink and
the remote — and **never said whether a TAG pointed at the served commit**. In this org the answer is
usually "not at the tip" (`tag-on-merge` tags the merge; the CHANGELOG commit sits one above), so a
body could call a pin *"merged and tagged"* with no part of the currency answer disagreeing. I hit
exactly that: a pin wave was BLOCKED by `design-pintag` for an untagged `dotgithub` pin while the
currency report had called every pin current.

**What the report now says**

- Per NOT-CURRENT pin: `; tag <name>` when a tag points at the **served** commit, otherwise
  `; no tag at served` — stated, never omitted.
- Head, over ALL leaves: `tags at served: N of M leaf pin(s) (K without — a CHANGELOG tip sits one
  commit above its tag, which design-pintag judges)`. This is what makes an **all-current** run
  answer the tag question, which is the case the issue is about.

**Where the fact comes from, and what it is not**

- `git ls-remote --tags <url>`, **once per URL for the run** (cached), read in its **PEELED** form
  (`<ref>^{}`) exactly as `resolveUpstreamRef` already prefers — comparing a commit against an
  annotated tag's object would report every annotated tag as pointing nowhere. The test tags with
  `-a` precisely to prove the peel.
- A pin whose intent names a tag carries that tag as the fact, without a second lookup.
- **No second policy**: `design-pintag` owns the state machine that explains an untagged pin (a
  CHANGELOG tip one above its tag, a recorded census exception). The report states the underlying
  fact and points at the gate for the verdict; it does not grow states, verdicts or census rows.
- An unreachable remote yields `no tag at served` for that repo and leaves the currency **verdict**
  untouched — the verdict never rested on the tag.

Diff, item by item: `candy/plugin-task/verbs.go` (the `pin.tag` field, the cached `remoteTagIndex`,
the per-pin clause, the head tally); `candy/plugin-task/currency_test.go` (the new test); and
`candy/plugin-task/pin_closure.go` — the round-1 R1 fix described below, which is a separate defect
the validator's block surfaced. No dependency changes.
