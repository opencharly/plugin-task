# 2026.276.1007 — feat(prune): add verb:prune — reap merged-upstream session worktrees + branches

## Summary

Adds `verb:prune` — the FIFTH generic, domain-neutral maintenance verb — to
`plugin-task`. It garbage-collects **merged-upstream session worktrees + branches**
across a project root and every submodule.

### Why (RCA, `opencharly/opencharly#342`)

The session close-out contract ("remove YOUR worktree, delete the merged branch")
is **prose an agent self-enforces**. It is NOT executed when:

- a session is **auto-closed** at the validator's block threshold;
- a fix lands on a **NEW branch/PR superseding** an abandoned one;
- a session **simply ends**.

Nothing swept, so worktrees + branches accumulated without bound. Measured on one
umbrella checkout (2026-10-03): **108 session worktrees** across 29
`.worktrees/<slug>/` directories and **1009 local branches** (415 defaults + 594
non-default; 276 CLOSED-only, 303 NO-PR). Nothing reported it: `.worktrees/` is
git-ignored, so the drift was invisible to `git status`, CI, and `charly task
verify`. `verb:prune` is the ONE mechanical control the contract lacked.

### Fail-safe by construction

It removes a worktree/branch ONLY when the merge is **PROVEN**:

- the tip is an **ancestor of `base`** (`origin/main`), OR
- its PR is **MERGED** and its tip is **contained in the merged head** — the
  **squash-merge case git ancestry alone cannot see**.

A branch carrying commits **BEYOND** a merged head (unmerged local work), or a
worktree with **modified tracked files**, is **never** touched. If `gh` is
unavailable (no auth / offline / non-GitHub origin) the sweep prunes **strictly
LESS, never more**. `include_closed` (off by default) additionally reaps abandoned
CLOSED-PR worktrees; `local_only` skips GitHub entirely. `MODE=report` (default)
is a dry run.

### What each safety guarantee's test proves

- `IncludeClosedReapsAbandoned` — the CLOSED-PR reap arm: the abandoned
  branch+worktree survive WITHOUT `include_closed`, and are reaped WITH it.
- `UntrackedForceDiscardsDisclosed` — the force path: a merged worktree carrying an
  untracked file is reaped, the untracked file is discarded, and the report
  DISCLOSES it (`discards 1 untracked entry`).
- `ModifiedTrackedSkipped` — a merged worktree with a MODIFIED tracked file is never
  destroyed (report names the skip).
- `DetachedWorktreeSkipped` — a merged branch's worktree in DETACHED HEAD is
  skipped (no branch to prove merged).
- `CwdWorktreeSkipped` — a merged worktree the process is STANDING INSIDE is
  skipped (never removed out from under the caller).
- `SubmoduleSwept` — the submodule loop in `pruneRepos`/Pass 1/Pass 2 is real: a
  merged worktree + branch of a CHECKED-OUT submodule is reaped, the submodule
  remains intact.
- `GHListPRsForDir_Live` — the real `gh` shell-out / URL→slug / JSON-decode /
  branch-keying path (LIVE against `opencharly/plugin-task`, or SKIP cleanly when
  `gh` is unauthenticated — R7a).
- `BeyondMergedHeadKept` / `LocalOnlyMissesSquash` / `GhUnavailableIsConservative` —
  the prune-strictly-LESS guarantees.

### A skipped worktree keeps its branch

`ModifiedTrackedSkipped` / `DetachedWorktreeSkipped` / `CwdWorktreeSkipped` skip the
worktree; because the skipped worktree still has its branch checked out, Pass 2 sees
it in-use and does NOT delete the branch either (git refuses `branch -D` on a
checked-out branch). The branch reaps only once its worktree is gone.

### Untracked-file behaviour (disclosed)

`git worktree remove` REFUSES a worktree with untracked entries, so the reap of such
a worktree requires `--force`, which **discards those untracked files**. The tool
carries the count into the report (`discards N untracked entr{y,ies}`), so the
discard is never silent; a worktree with *modified tracked files* is skipped
entirely.
