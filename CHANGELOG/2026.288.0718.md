# 2026.288.0718 — fix(git-submodules): verify names the DIRECTION and the remedy for a gitlink/checkout mismatch (opencharly/opencharly#461)

## Summary

Closes opencharly/plugin-task#27.

`verb:git-submodules` in `verify` mode compares a value read from THIS repo's **index** — the recorded gitlink, `git ls-files -s <path>` — against the submodule checkout's **HEAD**. It reported every mismatch as one string, `HEAD <h> != gitlink <g>`, for two OPPOSITE defects and identical to what a genuinely broken pin produces.

The pair is coherent at `charly task sync`'s exit — `bump` materialises each advance (`switch --quiet --detach`) and stages it (`git add`) — and conflicts the moment the advances are **un-staged** while the checkouts stay advanced, which the sanctioned branch flow does by design (`git switch -c <b> origin/main`, `git reset`, `git stash pop`, an aborted commit). MEASURED on the 429-submodule umbrella:

```
$ charly task policy-b                                   # 20 advances staged, then un-staged by a fresh branch off origin/main
  [fail] check — policy B holds
      verify: 20 failure(s): charly: HEAD 39292c822 != gitlink 0dd549ea1; dotgithub: HEAD c906bfc3a != gitlink 4c7237ba4; … (20 rows)
rc=1

$ git add -u                                            # re-stage exactly those 20; nothing else touched
$ charly task policy-b
  [pass] check — policy B holds
rc=0
```

The gate was right to be red and named the wrong thing: a tree whose pins were CORRECT read as a broken one, and the only command the reader needed (`git add`) was never named.

`gitlinkMismatchClass` now answers the one question the objects CAN answer — the DIRECTION — and names each remedy: `unstaged advance` (checkout ahead: `git add` records it, `git submodule update` discards it), `checkout behind the index` (`git submodule update`), `off its recorded gitlink`, and an explicit `unverifiable here` when the recorded pin is absent locally rather than folding it into either answer. It stays a FAIL in every case — a commit that records the old pin is still wrong. The two states are object-identical, so the report gives the direction plus BOTH remedies instead of guessing a cause, and `classTally` renders a long failure list as a distribution.

**This is the prerequisite for the pin-contract replacement now in design:** a currency-aware workflow that advances checkouts before the index agrees would hit exactly this wall, so the gate must be able to say which side moved.
