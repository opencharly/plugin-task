# 2026.296.1852 — feat(git-submodules): advance an unmaterialized pin in the index, so a wave needs no checkout

Closes #37

## Summary

`charly task sync` — the bump verb that advances a pin — REFUSED to advance a path with no checkout. The pin lives in the superproject's **index**, but the advance reached it through the **checkout**, so a path with no checkout had no tip to move and the whole run failed loud ("not an initialized checkout"). The consequence was the umbrella's own standing constraint, *"A WAVE NEEDS THE FULL SET"*: to move one pin, a wave had to materialize every repo — 431 of them, about 2 G and two minutes.

The pin IS the index entry: `git ls-files -s` reads it, `verify` judges it there, the currency report reads it there. So advancing it never needed a checkout.

- A **LEAF** advances to the tip its remote serves for its `branch=` (`git ls-remote <url> refs/heads/<branch>`), recorded with `git update-index --add --cacheinfo 160000,<sha>,<path>`.
- An **EDGE** (a `pin_map` entry) advances to the twin the SOURCE's tree records; a source with NO checkout is refused **by name**, with the command that materializes it, because a tree that is not there cannot be read.
- A path **with** a checkout is still rolled **in that checkout**, so the checkout and the index keep agreeing; a path with **no** checkout is advanced **in the index**, and `git submodule update --init <path>` brings the checkout to it afterwards. The order after a wave is therefore **sync -> init -> verify**.

The legacy fail-loud precondition over a merely unmaterialized path is deleted in the same cutover. The fail-loud discipline for everything the verb **cannot** advance is unchanged: an unjudgeable path (no `branch=`), a remote that does not serve the branch, a missing url, an unreadable source twin — each still fails the run, because a sync over a tree it could not fully advance must never report success.

charly#768's invariant is untouched **by construction**: no git operation ever runs inside a directory that has no checkout of its own, so git's walk-up to the superproject stays impossible.

**What this change does not do.** It does not change the pin contract's states, the producer-first leg order, or the treatment of a `blocked-by` pin. It materializes nothing and fetches no object into a checkout; the only network call is the remote branch read a leaf's advance needs. The umbrella's own three places that state the wave's order (sync -> init -> verify) are corrected in the umbrella's leg, after this change has reached the umbrella's binary.
