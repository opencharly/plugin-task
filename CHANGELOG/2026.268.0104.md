# 2026.268.0104 — feat(verbs): add the four generic maintenance verbs

## Summary

Add four **generic, domain-neutral maintenance verbs** to `plugin-task`, so a
repository can replace its maintenance shell scripts with declarative plan steps —
the second half of the operator-directed task-runner cutover (after
`kind:task`/`command:task`/`verb:task` in PR #2).

| Capability | Input def | Purpose |
|---|---|---|
| `verb:git-submodules` | `#GitSubmodulesInput` | status / bump / verify `.gitmodules` pins, incl. a policy-B comparison of a repo's pins against a pinned checkout's gitlinks |
| `verb:file-parity` | `#FileParityInput` | check / sync that paired files are byte-identical |
| `verb:splice-region` | `#SpliceRegionInput` | splice a marked region from a fragment into a target |
| `verb:module-pins` | `#ModulePinsInput` | adopt a source `go.mod`'s require pins across every module a glob matches, then tidy |

Every verb is parameterized by the **repo's own data** (paths, pairs, pins) carried
in its authored input, so the plugin stays reusable by any repository — no org
name, repo name, or distro list is baked in (R3 / the kernel-plugin boundary law).

**Files:**
- `candy/plugin-task/schema/task.cue` — the four self-contained `#<Name>Input` defs.
- `candy/plugin-task/{verbs.go,verbs_test.go}` — handlers, OpRun dispatch, tests.
- `candy/plugin-task/plugin.go` — advertises the four capabilities + routes them.
- `candy/plugin-task/params/cue_types_gen.go` — regenerated.
- `candy/plugin-task/charly.yml` — description + ADE probe updated.
- `scripts/gate-task.sh` — extended to drive `command:task` + all four verbs live.
- `.github/workflows/deploy.yml` — pins charly `v2026.267.2313`; runs the gate.
- `README.md` — documents the four verbs with authored examples.

## How tested

### Module gates

```
$ gofmt -l .        # empty
$ go vet ./...      # exit 0
$ go test ./...
ok  	github.com/opencharly/plugin-task/candy/plugin-task
```

The unit suite covers every verb: `git-submodules` status + a missing-twin verify
failure; `file-parity` drift-fail + sync-then-pass; `splice-region`
sync/idempotence/stale-check + missing-region; `module-pins` stale-check +
adopt-and-tidy + missing-source-key; plus `requireVersion` in BOTH the block
(`require ( … )`) and single-line (`require M vX`) forms.

### The in-repo live R10 gate — all four verbs + command:task execute live

`scripts/gate-task.sh` (run by `.github/workflows/deploy.yml`) clones charly pinned
to **`v2026.267.2313`** (the tag that compiles `candy/plugin-task` into the
binary), `-replace`s the plugin module with **this working tree** (so the artifact
under test IS the changed source), builds the binary, and drives the changed code
paths on a real git fixture:

```
$ bash scripts/gate-task.sh
== fetching charly v2026.267.2313 (compiles candy/plugin-task in) ==
== building charly with candy/plugin-task compiled in from the working tree ==
== charly task list ==
== verb:git-submodules verify (stale -> must FAIL) ==
task pins-verify: 1 step(s), 1 failed
  [fail] check — the pin holds
== verb:git-submodules bump (must move the pin to src's twin) ==
== verb:git-submodules verify (now current -> must PASS) ==
== verb:git-submodules verify (missing twin -> must FAIL loudly, never vacuous) ==
task missing-pin: 1 step(s), 1 failed
  [fail] check — the missing twin fails
== verb:file-parity (identical must PASS, drift must FAIL) ==
task parity: 1 step(s), 1 failed
  [fail] check — the pair is identical
== verb:splice-region (stale -> check must FAIL, sync -> current) ==
task splice-check: 1 step(s), 1 failed
  [fail] check — the region is current
== verb:module-pins (stale -> must FAIL, adopt -> must PASS) ==
task mods-check: 1 step(s), 1 failed
  [fail] check — the pins hold
gate-task: PASS — command:task + all four maintenance verbs executed live against charly v2026.267.2313
```

Every changed path has a live POSITIVE and NEGATIVE in the gate:
- `git-submodules`: verify fails stale → bump adopts src's twin → verify passes →
  verify fails LOUDLY on a pinned path with no gitlink (never a vacuous pass).
- `file-parity`: passes identical → fails drift.
- `splice-region`: `check` fails on a stale target → `sync` rewrites the region
  (leaving no stale text) → `check` passes.
- `module-pins`: `check` fails stale → `sync` adopts the pin → `check` passes.

### The CUE schema gate enforces each input at dispatch

A bogus field is rejected loudly (the self-contained schema is NOT decorative):

```
$ charly task bogus
  [fail] check — bogus field must be rejected
    message: plugin verb:git-submodules: plugin_input fails #GitSubmodulesInput:
             #GitSubmodulesInput.bogus_field: field not allowed
```

### Out-of-process manifest gate

`charly box validate` against the pinned charly (out-of-process) reports the candy
manifest + plugin block clean.

## Rulebook compliance

- **R0 skills:** `/charly-internals:plugin`, `/charly-internals:go`,
  `/charly-internals:git-workflow`, `/charly-check:check`,
  `/charly-internals:strict-policy`, `/charly-internals:cutover-policy`.
- **R1 RCA (both anomalies fixed in-tree):** the vacuous-pass defect in
  `git-submodules verify` (empty == empty when a gitlink is missing on either
  side) was caught by the unit test `TestGitSubmodules_VerifyPolicyB` and is now
  covered by BOTH a negative unit assert and a live gate case; `requireVersion`
  not matching the single-line `require M vX` form was caught by the unit suite.
  A third defect — `module-pins` flagging a module with no key require as stale —
  was caught by the LIVE gate (the post-adopt check failed on a stub module) and
  is fixed by skipping modules with no key require (the former sweep's contract).
- **R2 no out-of-scope:** the four verbs are the complete operator-directed batch;
  the umbrella's `scripts/*.sh` deletion follows in its own PR once this lands.
- **R3 no duplication:** each verb is ONE implementation, parameterized by repo
  data; the git-submodules pin logic mirrors the former `scripts/sync-gitlinks.sh`
  semantics (incl. its documented shallow-clone SHA fetch) as a declared verb, not
  a second engine.
- **R4 no workaround:** a missing gitlink FAILS LOUDLY rather than comparing
  empty to empty; `module-pins` adopts pins with `go mod edit` (which `go mod
  tidy` alone cannot do — the reason the former sweep existed).
- **R5 hard cutover:** the verbs are additive here; the umbrella scripts are
  deleted in the dependent PR.
- **R6 git safety:** `feat/` branch + PR; no force-push, no hook bypass.
- **R7 prove the change:** the live gate asserts every changed path with a
  positive AND a negative (see the gate section above); the unit suite fails
  without each verb.
- **R8 artifact invariants:** `params/cue_types_gen.go` is regenerated from the
  CUE source (a clean `cue exp gengotypes`); `charly box validate` is clean.
- **R9 binary == source:** the gate builds the binary with the plugin module
  `-replace`d to THIS tree, so the executed code is the changed source.
- **R10 disposable + coverage:** the live gate executes all four verbs + the
  command path end to end on a disposable git fixture.
- **RDD:** the verbs were proven live against a real checkout before landing.
- **ADE / SDD:** the candy keeps a non-empty `description:` + deterministic
  `check:` steps; the CUE schema is the single source, params generated.
- **Kernel/plugin boundary law:** zero core/sdk change — the verbs live entirely
  in the plugin candy; dispatch is the host's existing generic `plugin:` envelope.
- **CHANGELOG:** `tag-on-merge` writes `CHANGELOG/<calver>.md` from this body.
