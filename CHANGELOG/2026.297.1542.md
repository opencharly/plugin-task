# 2026.297.1542 — test(task): close and drain the pipes the skipped-step CLI test opens

## Summary

This is the successor to PR #45 (merged as `7e26679`, tag `v2026.297.1509`), and it carries two things: the stderr-capture fix that #45's PASS asked for, and the round-1 CI failure that fix exposed.

**1. The CI `go` job on this branch went red, and the finding is mine.** staticcheck flagged a dead condition in the stderr assertion this branch added:

```
candy/plugin-task/skipped_test.go:232:5: S1009: should omit nil check;
len() for nil slices is defined as zero (staticcheck)
```

RCA. The **mechanism** is a dead condition: `io.ReadAll` never returns nil, so `stderrReport != nil && len(stderrReport) > 0` says exactly what `len(stderrReport) > 0` already said. The **missed control** is the honest part: this repo's pre-push gate ran `go build`, `go test`, `gofmt -l .` and `go vet` — and not `golangci-lint`, which is what the CI job `go` runs. The lint step lived only in CI, so a finding CI would raise was invisible until CI raised it. The **blast radius** was this PR's whole landing: the `validate / arm` job failed behind it (its step is "fail on any check that did not pass"), so auto-merge never armed. The **root fix** is both halves: the dead check is gone, and the control itself is fixed — `AGENTS.md`'s gate list now names CI's `go` job steps, the linter and the vet, so the local gate runs what CI runs, with the linter under the toolchain the module's own `go.mod` declares (golangci-lint v2.13.2 cannot read the export data of a newer GOROOT) and its pinned version left where it already lives, in `.github/workflows/ci.yml`.

**2. The validator's own review of this branch raised three more notes on the same capture**, and a finding raised on a PR is never filed away: the dead `!= nil` check above; the globals reassigned without a restore on every path, so a panic in the run under test would leave the NEXT test in the binary writing its output into a pipe nobody reads; and an early `t.Fatalf` that leaked the pipes, because there were no defers.

All three are fixed, and the fix is ONE shape rather than four. The capture was written four times in this package (`skipped_test.go` twice, `cli_test.go` once, `plugin_test.go` once), and the second copy was already wrong — that is how the leaked write end in PR #45 happened. `captureStreams` is now the only capture: it keeps both ends of both pipes, closes the write ends before the drain (`io.ReadAll` returns EOF only when every write end is closed, and an undrained pipe blocks the next writer), and restores the globals on every exit path including a panic. The four call sites use it, and the inline copies are deleted in the same cutover.

The stdin captures in `runner_test.go` are a different behavior — they feed `os.Stdin`, they do not capture the reporter's output — and they are untouched; the sweep below names every `os.Pipe` left in the package to show that.
