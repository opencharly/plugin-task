# 2026.296.1911 — fix(git-submodules): classify the bump's source by its CHECKOUT, not by its roll

Closes #39

## Summary

Head `525c47f05f08e4d3a0e55db371955ee7a15e6902` — 3 files changed, 162 insertions(+), 5 deletions(-).

The wave-3 state machine (opencharly/plugin-task#37, PR #38) separated two facts that must not be reported as one: a source that did NOT roll has STALE gitlinks, and a source with NO CHECKOUT has UNREADABLE ones. It classified the source by the ROLL. A source with no checkout AND no `branch=` leaves phase 1 before the roll, so it was reported as a STALE source: the refusal blamed gitlinks that were never there and named no remedy.

The CHECKOUT is now read FIRST, and the roll only refines it: a source with no checkout can never be stale, whatever its `branch=` says and whatever the advance did. The refusal names the missing checkout and the one command that materializes it — `git submodule update --init <path>`.

**What this change does not do.** The refusal itself is unchanged: the run still fails, the verb still refuses to pin from a source it cannot read, and it still names the edge the caller declared. The fail-loud invariant is unchanged. The edge, the pin contract's states, and the wave-3 advance path — a LEAF to the tip its remote serves for its `branch=`, an EDGE to the twin the source's tree records — are unchanged. This is the follow-up to the validator's finding on #38: it is fixed here, not filed away.
